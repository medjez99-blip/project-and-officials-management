# وزارة التربية والتعليم — متابعة مشاريع البنية التحتية

**App name:** `project-and-officials-management`

بوابة ويب عربية (RTL) لمتابعة مشاريع البنية التحتية، تسجيل الزيارات الميدانية
بالصور والموقع الجغرافي، وإدارة المسؤولين والصلاحيات.

**المعمارية:** تطبيق ويب بطبقة **local-first** — كل كتابة تُحفظ فوراً في المتصفح
(`localStorage` + `IndexedDB`) ثم تُزامَن في الخلفية مع **Supabase**
(Auth + Postgres + Storage). يعمل دون اتصال، ولا تُفقد أي كتابة عند انقطاع الشبكة.

---

## الميزات

- 🔐 مصادقة عبر **Supabase Auth** بصلاحيتين: **مسؤول متابعة المشاريع** و**تقني**.
- 🔄 مزامنة تلقائية ثنائية الاتجاه مع Supabase — عند الإقلاع، كل 30 ثانية،
  وعند استعادة التركيز/الاتصال.
- 📊 لوحة إحصاءات وتذكيرات آلية بالمواعيد المتأخرة والقريبة.
- 🔎 بحث وفلاتر (الحالة، الأولوية، الوحدة) وترتيب متعدد.
- 🖼️ سجل زيارات لكل مشروع: ملاحظات، صور مختومة بالتاريخ والموقع، ورابط الخريطة.
- ☁️ الصور تُرفع إلى bucket خاص على Supabase Storage، ويُعرَض للمستخدمين
  عبر روابط موقّعة (signed URLs).
- 👥 إدارة التقنيين من قِبل مسؤول متابعة المشاريع عبر Edge Function (`admin-users`):
  إنشاء، حذف، تعديل الصلاحية، إعادة تعيين كلمة المرور.
- 📤 تصدير/استيراد JSON، تصدير CSV، نسخة احتياطية، وحذف شامل.
- 📱 واجهة متجاوبة بالكامل (RTL، Light mode فقط) + PWA قابل للتثبيت.
- 🟢 بادج مزامنة في الشريط العلوي: متزامن · قيد الانتظار · مزامنة… · غير متصل.

## الحسابات

**لا تُزرع أي حسابات تلقائياً.** تُنشأ من قِبل مسؤول متابعة المشاريع عبر واجهة
«التقنيون» داخل التطبيق. لا يوجد تسجيل عام — يجب التواصل مع مسؤول متابعة المشاريع
للحصول على حساب.

> أول حساب مسؤول متابعة المشاريع يُنشأ يدوياً من Supabase Dashboard. راجع `OPERATIONS.md` §2.7.

## التشغيل محلياً

1. أضف بيانات مشروع Supabase إلى `config.js` (راجع `OPERATIONS.md` §2.8).
2. شغّل خادم محلي:

   ```bash
   python -m http.server 8080
   # ثم افتح http://localhost:8080
   ```

> **لا** تفتح `index.html` مباشرة عبر `file://` — المصادقة وتحديد الموقع
> والـ Service Worker كلها تتطلب `http://` أو `https://`.

## النشر على Netlify

1. ارفع المجلد إلى المستودع.
2. Netlify → **Import from Git** → اختر المستودع.
3. **Build command:** (فارغ) — **Publish directory:** `.`
4. Deploy.

بعد النشر: افتح الموقع → **Ctrl+Shift+R** → سجّل الدخول بحساب المسؤول متابعة المشاريع.

راجع `OPERATIONS.md` §2.9.

## النشر على GitHub Pages (بديل)

1. أعد تسمية `إدارة المشاريع والمسؤولين.html` إلى `index.html` (إن لزم).
2. ارفع الملفات إلى المستودع.
3. **Settings → Pages** → `main` + `/ (root)`.
4. في `index.html`، عدّل تسجيل الـ Service Worker:
   `navigator.serviceWorker.register('./sw.js', { scope: './' })`
   (بدلاً من `/sw.js` مع `scope: '/'`) — GitHub Pages يستضيف تحت مسار فرعي.

## بنية المشروع

```
index.html        # الهياكل (auth, topbar, جدول، مودالات)
main.css          # التنسيقات (RTL، مكوّنات، بادج المزامنة)
config.js         # SUPABASE_URL + SUPABASE_ANON_KEY (يُعدّل عند النشر)
supabase.js       # عميل Supabase (ES module)
core.js           # الحالة، IndexedDB، المصادقة، طبقة المزامنة، معالجة الصور
ui.js             # الرسم: الإحصاءات، الجدول، الزيارات، المودالات
app.js            # الأحداث، التصدير/الاستيراد، لوحة المفاتيح، PWA install
sw.js             # Service Worker (cache shell + VERSION)
manifest.json     # PWA manifest
netlify.toml      # Headers + SPA fallback
OPERATIONS.md     # دليل التشغيل الكامل ← ابدأ من هنا
todo.txt          # سجل الترحيل والمهام المكتملة
```

> **ترتيب تحميل السكربتات مهم:**
> `config.js` ← `supabase.js` (module) ← `core.js` ← `ui.js` ← `app.js`

## ملاحظات

- البيانات **متزامنة عبر Supabase**؛ الصور مخزنة في bucket خاص (`visit-photos`).
  كل متصفح يحتفظ بنسخة محلية كطبقة أولى للعمل دون اتصال.
- تحديد الموقع يتطلب HTTPS أو `localhost` وسيطلب إذن المستخدم.
- المصادقة مُدارة بالكامل بواسطة Supabase Auth. لا تُخزَّن كلمات المرور في المتصفح.
- سياسات RLS صارمة: كل تقني يرى مشاريعه فقط؛ مسؤول متابعة المشاريع يرى الجميع.
- النسخ الاحتياطي التلقائي: Supabase تحتفظ بنسخ يومية (7 أيام على الخطة المجانية).
