# وزارة التربية والتعليم — إدارة المشاريع والمسؤولين
App name: project-and-officials-management
بوابة ويب عربية (RTL) لمتابعة المشاريع التربوية، تسجيل الزيارات الميدانية
بالصور والموقع الجغرافي، وإدارة المسؤولين والصلاحيات.

تطبيق ويب (HTML + CSS + JavaScript) مع طبقة **local-first**:
تُحفظ البيانات فوراً في المتصفح (`localStorage` للمشاريع، `IndexedDB` للصور)،
ثم تُزامَن في الخلفية مع **Supabase** (Auth + Postgres + Storage).
هذا يعني: يعمل دون اتصال، ولا تُفقد أي كتابة إذا انقطع الشبكة.

---

## الميزات

- 🔐 مصادقة عبر **Supabase Auth** بصلاحيتين: **مدير النظام** و**مستخدم**.
- 🔄 مزامنة تلقائية ثنائية الاتجاه مع Supabase — عند الإقلاع، كل 30 ثانية، وعند استعادة التركيز/الاتصال.
- 📊 لوحة إحصاءات وتذكيرات آلية بالمواعيد المتأخرة والقريبة.
- 🔎 بحث وفلاتر (الحالة، الأولوية، الوحدة) وترتيب متعدد.
- 🖼️ سجل زيارات لكل مشروع: ملاحظات، صور مختومة بالتاريخ والموقع، ورابط الخريطة.
- 📤 تصدير/استيراد JSON، تصدير CSV، نسخة احتياطية، وحذف شامل.
- 👥 إدارة المستخدمين وترقية الصلاحيات (للمدير فقط).
- 📱 واجهة متجاوبة بالكامل مع الوضع الليلي غير المطلوب (Light only).

## الحسابات

لا تُزرع أي حسابات تلقائياً. تُنشأ الحسابات من قِبل مدير النظام عبر
واجهة «المستخدمون» (تستدعي Edge Function على Supabase). لا يوجد تسجيل
عام — يجب التواصل مع مدير النظام للحصول على حساب.

## التشغيل محلياً

يكفي فتح `index.html` في المتصفح. للاختبار الكامل (تحديد الموقع، IndexedDB)
يُفضّل تشغيل خادم محلي:

```bash
python -m http.server 8080
# ثم افتح http://localhost:8080
```

## النشر على GitHub Pages

1. أعد تسمية الملف `إدارة المشاريع والمسؤولين.html` إلى `index.html`.
2. ارفع الملفات إلى المستودع.
3. من **Settings → Pages** اختر الفرع `main` والمجلد `/ (root)`.
4. سيصبح الموقع متاحاً على `https://<username>.github.io/<repo>/`.
## إعداد Supabase (لمرة واحدة عند فتح مشروع جديد)

1. أنشئ مشروعاً جديداً على <https://supabase.com/dashboard>.
2. **SQL Editor**: نفّذ سكربت المخطط الكامل (جداول + سياسات RLS + دوال + triggers).
3. **Storage**: أنشئ bucket خاصاً باسم `visit-photos` + سياساته الأربع.
4. **Authentication → Settings**: عطّل التسجيل العام. أنشئ أول مستخدم من **Users**، ثم أضف صفّه في `profiles` بدور `admin`.
5. **Edge Functions**: انشر الدالة `admin-users` (تُدار بـ `service_role` تلقائياً).
6. انسخ **Project URL** و**anon key** من **Project Settings → API** إلى `config.js`.
7. انشر الموقع. سجّل الدخول بحساب المدير.
## بنية المشروع

```
index.html # الواجهة والهياكل (modals، جدول، شاشة الدخول)
main.css # التنسيقات (RTL، مكوّنات، استجابة)
config.js # SUPABASE_URL + SUPABASE_ANON_KEY (يُعدّل عند النشر)
supabase.js # عميل Supabase (ES module)
core.js # الحالة، الأدوات، IndexedDB، المصادقة، طبقة المزامنة
ui.js # الرسم: الإحصاءات، الجدول، الزيارات، المودالات، البادجات
app.js # الأحداث، التصدير/الاستيراد، لوحة المفاتيح، الإقلاع
sw.js # Service worker (cache shell)
manifest.json # PWA manifest
```

> ترتيب تحميل السكربتات مهم: `config.js` ← `supabase.js` (module) ← `core.js` ← `ui.js` ← `app.js`.

## ملاحظات

- البيانات **متزامنة عبر Supabase**؛ الصور مخزنة في bucket خاص (`visit-photos`).
  يحتفظ كل متصفح بنسخة محلية (localStorage + IndexedDB) كطبقة أولى للعمل دون اتصال.
- تحديد الموقع يتطلب HTTPS أو `localhost` وسيطلب إذن المستخدم.
- المصادقة مُدارة بالكامل بواسطة Supabase Auth. لا تُخزَّن كلمات المرور في المتصفح.
- سياسات RLS صارمة: كل مستخدم يرى مشاريعه فقط؛ مدير النظام يرى الجميع.
